# 端点授权白名单（scripts/check-endpoint-authorization.sh 读取）
#
# 用途：登记「故意不写 @AinerAuthorize、也不写 @EndpointAccess」的 Controller 方法。
# 未登记且没有源码声明的 handler 一律判违规并 exit 1。
#
# 格式（每行一条，字段之间用空白分隔）：
#
#     <类#方法>  <理由>
#
#   * <类#方法>：`类` 可以是简单类名或全限定类名，`方法` 是 Java 方法名；
#     两者都支持 `*` 通配（例如 `WorkspaceController#*`、`*Controller#page*`、`*#*`）。
#     必须包含且只包含一个 `#`，否则脚本失败关闭。
#   * <理由>：必填，写清「为什么这里可以没有 @AinerAuthorize / @EndpointAccess」，
#     要能指到具体机制（安全链、白名单 bean、专用过滤器、条件门禁……）。
#     禁止空理由，禁止「临时」「为了通过门禁」「与既有代码保持一致」这类无法审查的措辞。
#   * 以 `#` 开头的行是注释；理由文本内允许出现 `#`（只按第一个 `#` 切分类与方法）。
#
# 使用边界（详见 docs/security.md §3.4）：
#
#   1. 白名单只影响静态门禁，不改变运行期裁决。运行期 FAIL_CLOSED 只认源码里的
#      @AinerAuthorize / @EndpointAccess；白名单里的方法仍会被运行期拒绝，
#      除非它由外层安全链或应用服务自己完成鉴权。
#   2. 白名单是「运行期拦截器覆盖不到」的场景的兜底（不装配 ainer-module-authorization
#      的应用、第三方/生成代码），不是让新端点免于声明的捷径。
#   3. 登记项若在扫描范围内没有任何匹配的 handler，脚本按失败关闭报「过期登记」。
#
# ---------------------------------------------------------------------------
# 当前登记项：Authorization Server 独立应用（不依赖 ainer-module-authorization，
# 因此无法使用 @AinerAuthorize / @EndpointAccess；其端点由本应用自己的
# SecurityFilterChain 按路径精确强制，见 docs/security.md §4）。
# ---------------------------------------------------------------------------

AinerLoginPageController#*        浏览器登录页 GET /login：由 authorizationServerDefaultSecurityFilterChain 显式 permitAll（OAuth2 授权码流程入口，本身不返回任何业务数据）；该应用不装配 AinerAuthorizeInterceptor。
OAuthBrowserClientController#*    /internal/oauth-browser-clients/** 由 internalSecurityFilterChain 要求 SERVICE 主体持 SCOPE_browser-client-control.manage.all，其余 /internal/** 请求 denyAll。
AinerPasskeyEnrollmentController#* /internal/passkey-enrollment/** 由 internalSecurityFilterChain 要求 SERVICE 主体持 SCOPE_passkey.enrollment.manage.all。
AinerPasskeyRecoveryController#*  /internal/passkey-recovery/** 由 internalSecurityFilterChain 要求 SERVICE 主体持 SCOPE_passkey.recovery.request.all 或 SCOPE_passkey.recovery.approve.all（按路径分动作）。
AinerPasskeyRecoveryCodeController#* 自助恢复码控制面（默认关闭）：默认 SecurityFilterChain 要求已认证会话，签发侧另受 WebAuthn 条件 MFA 门禁约束；兑现侧刻意不要求 WebAuthn（用户已丢失设备），这是 ADR-0015 的既有设计而非权限码缺口。
CurrentAccessTokenRevocationController#* /api/me/access-token-revocations 由 accessTokenRevocationSecurityFilterChain 要求已认证，并经 AinerAdminAccessTokenActiveFilter 校验该 access token 仍为 ACTIVE。
