# ADR-0048：Packages 存储治理与 rc 链 Maven 制品退役基线

- 状态：Accepted
- 日期：2026-08-24
- 修订：ADR-0041 中关于 rc 链已部署制品保留的条款（本 ADR 取代其在该范围内的结论）
- 决策者：仓库负责人（2026-08-24 会话确认，选项 C）

## 背景

GitHub 免费版私有仓库的 Packages/Actions 共享 500MB 存储。2026-08-24 `v1.1.0` 发布时
deploy 连续五次 HTTP 402，随后包内容进入配额锁定状态（对既有版本文件的请求返回 404），
影响现有消费者解析历史版本。

量化盘点：

- Actions 制品与缓存合计曾达 ~1.7GB，已全部清空并建立防复发机制
  （housekeeping 工作流 + 发布构建去缓存，PR #36）；
- Maven Packages 本体实测 **377MB / 约 1296 文件 / 6 个版本**
  （0.1.0-rc.1、0.1.0-rc.2、0.1.0-rc.3、0.1.0、0.2.0、1.0.0），其中两个发行物 fat jar
  每版约 84MB 是主要占用，平均每版本足迹约 63MB；
- 包体基线使缓存/制品可用余量只剩约 123MB，任何并发写入即触发超限。

ADR-0041 与当时状态记录规定：`rc.1` 为 withdrawn/non-qualifying，"禁止消费、复用、移动或
覆盖"；`rc.2`/`rc.3` "保持不可变，只作为升级/回滚的已发布起点"。该保留决定做出时没有
存储预算约束的对抗性事实。

## 决策

1. **退役 GitHub Packages 中 rc 链三个版本的 Maven 制品**：对全部 reactor 包删除
   `0.1.0-rc.1`、`0.1.0-rc.2`、`0.1.0-rc.3` 六组中的前三组共 26×3 个版本条目，
   预计释放约 190MB。
2. **保留范围不受影响**：
   - git 上的 annotated tag `v0.1.0-rc.1/rc.2/rc.3` 与全部源码历史；
   - rc.2 / rc.3 的 immutable GitHub Release 及其各 16 个签名证据资产（源码 SHA、SBOM、
     provenance、checksums——它们记录的是发布身份与证据链，不依赖 Maven 二进制持续可取）；
   - 消费者仓库 git 历史中的完整升级/回滚演练序列（rc.2 → rc.3 → rc.2 等提交证据）。
3. **放弃的能力**：从远端注册表重新消费或复验 `rc.1/rc.2/rc.3` Maven 制品的路径不复存在。
   后续升级/回滚矩阵自 `0.1.0` GA 起算（相邻版本窗口，符合 ADR-0045）。
4. **存储预算规则**：包体退役后基线约 188MB；每次 minor/patch 发布增加约 63–65MB。
   发布前必须确认 Actions 缓存为 0 且无并发 CI；包体接近 450MB 时必须先做本 ADR 式的
   版本退役决策，不得依赖缓存清理腾位。

## 备选方案

- **付费扩容**（约 $0.008/GB/月）：技术上最简单，但负责人选择先以退役换取零成本运行；
  配额再次逼近时可重新评估。
- **只删 rc.1**：释放约 63MB，不足以恢复发布余量且保留条款同样被触碰，收益不成比例。
- **裁剪发布合同**（发行物 fat jar 不再入 Packages）：能长期降低每版足迹，但改变
  release-artifacts 合同与读回门禁，属独立工程变更，不在本次范围。

## 后果

正面：

- 包体降至约 188MB，为 `v1.1.0` 发布及后续一个 minor 周期提供充足余量；
- 解除内容锁定，恢复现有消费者对 `0.1.0/0.2.0/1.0.0` 的依赖解析；
- 存储治理有了明确的量化预算规则与自动化兜底（housekeeping + 无缓存发布构建）。

代价与风险：

- rc 链制品不可逆消失：任何声称"仍可从远端消费 rc.x"的历史表述自此失效，以本 ADR 为准；
- 若未来需要复验 rc 期升级行为，只能依据 git 历史、immutable Release 证据与状态文档记录，
  不能重放真实远端消费。

## 安全/数据/运维影响

- 不触及任何业务数据、密钥或审计记录；删除对象仅为 Maven 二进制制品与其签名伴随件。
- `rc.1` 的 withdrawn/non-qualifying 定性不变，且物理删除是其"禁止消费"的最强执行形态。
- 运维侧新增两条硬规则进 handoff §9：发布前缓存必须为 0；包体 >450MB 先退役再发布。

## 验收记录

- 删除执行后：剩余版本探测应仅含 `0.1.0/0.2.0/1.0.0` 三组；
- 内容锁定解除后：`ainer-dependencies-1.0.0.pom` 等既有版本文件请求返回 200；
- `v1.1.0` release workflow 重跑全绿并形成不可变 Release（后续状态记录留痕）。
