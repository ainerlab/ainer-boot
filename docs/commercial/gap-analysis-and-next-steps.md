# Ainer Boot 可售性差距分析与发展路线建议

> 状态：内部评估与**非权威建议** · 2026-08-22
> 动态状态唯一权威仍是 [`project-status.md`](../project-status.md)；本文回答的是
> 「距离可售卖还差什么、下一步先做什么」，供商业决策与开发排期讨论。

---

## 1. 结论先行

「足够好吗」取决于问的是哪件事：

| 问题 | 回答 | 依据 |
|---|---|---|
| 作为**自用工程基线**是否够好 | **是，超出预期** | 真实库零跳过门禁、签名供应链、双消费者升级回滚矩阵、fail-closed 安全架构——两个自有产品已走通「制品 → 业务上线」全程 |
| 作为**可对外售卖的产品**是否够好 | **否，差距明确且可列举** | 见下节五项缺口；其中最致命的不是代码能力，而是市场证据与管理面 |

## 2. 差距清单（按对销售的影响排序）

| # | 缺口 | 对售卖的影响 | 收口性质 |
|---|---|---|---|
| 1 | **无管理界面**（Studio 未交付；菜单/路由权限是非目标） | 致命——目标市场买家默认期待开箱管理页，第一个问题就是"页面在哪" | 大：独立产品线工程 |
| 2 | **无外部客户证据**（两个参考消费者均为自家） | 高——企业采购要参照案例，双自有消费者说服力有限 | 低：动作是找客户，不是写代码 |
| 3 | **通知无真实渠道**（默认日志发送器，SMS/Email 靠 SPI 自接） | 中高——企业买家必问"邮件/短信呢" | 低：一个真实 ChannelSender 实现 |
| 4 | **生产运维承诺缺位**（多节点 HA 未验证、告警未建） | 中——"上生产谁兜底"没有答案 | 中：部署验证 + runbook |
| 5 | **AI 只有网关层**（Agent 工具/RAG/Evaluation 在路线图） | 中——"AI-native"是定价叙事核心词，目前只有治理半边 | 中大：ADR-0034 后续切片 |
| 6 | 前端生态未闭环（SDK 有契约、无规模化真实前端消费） | 中 | 随 Studio 一并解决 |

## 3. 发展路线建议（三阶段）

### H1 —— 让「可售实体」成立（近期）

1. **发布 v1.2.0**：任务调度模块 + trusted-managers 兼容修正等主线成果发版（流程已成熟，
   消费者矩阵例行执行）
2. **落地首个外部消费者/客户项目**：最高杠杆动作。交付路径已被两个内部消费者验证，
   缺的是一个真实第三方案例与可引用证据。允许让利换案例
3. **通知渠道首个真实实现**（Email 或 Webhook 的 `ChannelSender`）：补掉买家必问项
4. **商业四决策拍板**：许可模式、分层定稿、定价、SLA 范围（见
   [`edition-tiers.md`](edition-tiers.md) §5）——纯决策，无工程量

### H2 —— 补商业化硬缺口（中期）

5. **Studio 最小切片**：登录 + 用户/角色/授权绑定管理页（后端 API 全部已就绪）。顺带
   打通 `@AinerAuthorize` 真实端点消费与资源 target resolver——授权引擎的收尾与此同路
6. **生产运维包**：双节点部署验证、告警基线（OWNER 缺失/撤销积压等既有指标接告警）、
   备份恢复演练 runbook
7. **AI 第二层场景切片**：Agent 工具调用治理或 RAG 检索授权二选一先做，让 AI 叙事从
   「治理网关」升级为「治理 + 场景」

### H3 —— 规模化（远期）

8. SCIM/SSO 企业集成、模板市场与 entitlement（P5）
9. 社区化运营决策（是否开源 core 引流）——需独立 ADR

## 4. 明确不建议做的

- **不要预建服务化设施**：无真实远程消费者时不建 remote adapter（仓库既有纪律）
- **不要为堆功能推迟销售**：H1 的第 2 条优先于一切能力纵深——工程能力已证明，缺的
  只是市场证据（这也是根 AGENTS.md 的既有立场）
- **不要把前端管理面做进主仓**：Studio 是独立产品线，边界不能糊
